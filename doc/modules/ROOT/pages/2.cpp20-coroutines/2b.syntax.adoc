This page teaches you to read and write a coroutine: the three keywords, a first coroutine, and the awaiter protocol that drives `co_await`.

== The Three Keywords

A function becomes a coroutine when its body contains `co_await`, `co_yield`, or `co_return`, signaling to the compiler that it requires coroutine machinery.

=== co_await

The `co_await` keyword awaits an operation and may suspend the coroutine until that operation completes. When you write `co_await expr`, the coroutine saves its state, pauses execution, and potentially allows other code to run. When the awaited operation completes, the coroutine resumes from exactly where it left off.

=== co_yield

The `co_yield` keyword produces a value and hands it to the promise. `co_yield e` means `co_await promise.yield_value(e)`, so the coroutine suspends only if the awaiter that `yield_value` returns does. This pattern creates *generators*: functions that produce sequences of values one at a time. A typical generator suspends after each value and pauses until someone asks for the next one.

== Your First Coroutine

The distinction between regular functions and coroutines matters because they behave fundamentally differently at runtime:

* A regular function allocates its local variables on the stack. When it returns, those variables are gone.
* A coroutine allocates its local variables in a *coroutine frame*, typically on the heap. When it suspends, those variables persist. When it resumes, they are still there.

== Awaitables and Awaiters

When you see expression `co_await aw`, the sub-expression `aw` is an *awaitable*.
The awaitable names the operation, but it does not decide how the coroutine suspends.
When expression `co_await aw` is evaluated, the compiler first uses `aw` to produce an *awaiter*.
If the promise type has a member `await_transform`, the compiler calls `promise.await_transform(aw)` and uses its result.
Otherwise it uses `aw` itself.
The `co_await` expressions that the compiler generates for initial suspend, final suspend, and `co_yield` skip this step.
Next, overload resolution looks for an `operator co_await`, member or non-member, that accepts that result.
If it finds one, its return value is the awaiter.
Otherwise the result itself is the awaiter.
The awaiter controls suspension and resumption through three member functions:

* `await_ready()` — Returns `true` if the result is immediately available and no suspension is needed.
* `await_suspend(handle)` — Called when the coroutine suspends; receives a handle to the coroutine for later resumption.
* `await_resume()` — Called when the coroutine resumes; its return value becomes the value of the `co_await` expression.

NOTE: Often the awaiter and the awaitable are the same object, as in the example below.
      A promise's `await_transform` can even make a plain `int` awaitable.

----

*Output:*

[role=output]
----
counter: 0
main: resuming
counter: 1
main: resuming
counter: 2
main: resuming
counter: 3
----

Study this execution flow:

1. `main` calls `counter`, passing the address of a xref:glossary.adoc#coroutine-handle[coroutine handle]
2. `counter` begins executing, prints "counter: 0", and reaches `co_await awaiter`
3. `await_ready()` returns `false`, so suspension proceeds
4. `await_suspend` receives a handle to the suspended coroutine and stores it in `main`'s variable `h`
5. Control returns to `main`, which now holds a handle to the suspended coroutine
6. `main` calls `h()`, which resumes the coroutine
7. The coroutine continues from where it left off, increments `i`, prints "counter: 1", and suspends again
8. This cycle repeats until `main` destroys the coroutine

The variable `i` inside `counter` maintains its value across all these suspension and resumption cycles.


NOTE: Only a coroutine can evaluate a `co_await` expression.
      The awaiter, however, is an ordinary object: it need not be a coroutine, or invoke one.


=== Standard Awaiters

The {cpp} standard library provides two predefined awaiters:

* `std::suspend_always` — `await_ready()` returns `false` (always suspend)
* `std::suspend_never` — `await_ready()` returns `true` (never suspend)
