= Quick Start
:page-mode: tutorial

== Requirements

=== Assumed Knowledge

* {cpp}20 coroutines, concepts, and ranges
* Basic concurrent programming

=== Compiler Support

CI tests these compilers. Older versions are untested.

* GCC 13+
* Clang 17+
* Apple-Clang (macOS 15+)
* MSVC 14.44+
* MinGW Clang (MSYS2)
* clang-cl
* Clang on FreeBSD 14.3 and 15.0

=== Dependencies

None. Capy is self-contained and does not require Boost.
The optional Asio interop header, `boost/capy/buffers/asio.hpp`, needs Boost.Asio.

On macOS and FreeBSD, Clang needs `-fexperimental-library` for `std::stop_token`.
The CMake build adds this flag, but a hand-written compile line must add it too.

== Minimal Example

Create a file `hello_coro.cpp`:

[source,cpp]
----
include::example$programs/quick_start_hello.cpp[tag=full]
----

== Build and Run

Capy is not installed as a system package, so build it first.
As the top-level project, the build also includes tests, examples, and benchmarks by default.
These options turn them off for a faster first build:

[source,bash,role=external]
----
cmake -B build -DBOOST_CAPY_BUILD_TESTS=OFF \
    -DBOOST_CAPY_BUILD_EXAMPLES=OFF -DBOOST_CAPY_BUILD_BENCH=OFF
cmake --build build
----

Replace both paths below with where you built Capy:

[source,bash,role=external]
----
g++ -std=c++20 -I/path/to/capy/include -o hello_coro hello_coro.cpp \
    /path/to/capy/build/libboost_capy.a -pthread
----

NOTE: If your program is built with CMake, add Capy with `add_subdirectory` or `FetchContent`, then link against `Boost::capy`.

Then run the compiled program:

[source,bash,role=external]
----
./hello_coro
----

Expected output:

[role=output]
----
The answer is 42
----

== What Just Happened?

1. `answer()` creates a suspended coroutine that returns 42
2. `greet()` creates a suspended coroutine that awaits `answer()`
3. cpp:run_async[]`(pool.get_executor())(greet())` starts `greet()` on the pool's xref:glossary.adoc#executor[executor]
4. `greet()` runs until it hits `co_await answer()`
5. `answer()` runs and returns 42
6. `greet()` resumes with the result and prints it
7. `greet()` completes, `pool.join()` returns, and `main()` exits

Both coroutines ran on the same executor because xref:glossary.adoc#affinity[affinity] propagated
automatically through the `co_await`.

== Error Codes Instead of Exceptions

I/O operations do not throw for expected failures, such as reaching the end of a stream.
They report the failure as a value instead: a cpp:results[], holding an error code followed by the payload.
A task of your own can do the same, and the caller unpacks the error code first:

[source,cpp]
----
include::example$snippets/quick_start.cpp[tag=error_codes,indent=0]
----

See xref:4.coroutines/4k.results.adoc[The results Type].
