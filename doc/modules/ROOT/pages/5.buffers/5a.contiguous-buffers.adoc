= Contiguous Buffers
:page-mode: explanation

The most efficient way to provide storage for bytes is a contiguous region: an array. 
While it is not always possible to efficiently compose a full message in a single contiguous region,
it is a good default. Capy offers two types for this purpose:

 * cpp:const_buffer[]: a handle to a contiguous sequence of bytes. I/O operations do not modify these bytes.
 * cpp:mutable_buffer[]: a handle to a contiguous region for storing bytes. I/O operations fill it.

Neither type owns the bytes. Each refers to storage that your program owns
and must keep alive.

Both types are present in header `<boost/capy/buffers.hpp>`. 


== Passing Handles

Objects of type cpp:const_buffer[] and cpp:mutable_buffer[] store a 
pointer to the beginning of a memory region and the size of the region measured in bytes.
This is reflected in how they are constructed and how they are copied.

----

----

<2> Copies the pointer and the size.

Operations take the buffers by value, or store them by value as data members.
Only the handle is copied. The location of the bytes does not change.

== Lifetime Management

A buffer does not own, allocate, or copy the bytes it refers to. Destroying
the storage leaves every buffer referring to it dangling, just as destroying
a string leaves a cpp:string_view[std::string_view] dangling.

The contract for read and write operations in Capy is:

 * The user manages the lifetime of the byte storage.
 * I/O operations receive a handle to the storage and assume that it will be available for the entire duration
   of the asynchronous operations.
 * The storage must stay valid until the operation completes, not only until the call that started it returns.
   An asynchronous operation may touch the bytes at any point before it completes.

[source,cpp]
----
include::example$snippets/5a_contiguous_buffers.cpp[tag=good_management,indent=0]
----
<1> OK: The read happens at an unpredictable time. The coroutine must be resumed
    afterwards, so its frame (containing the array) outlives the read operation.

[source,cpp]
----
include::example$snippets/5a_contiguous_buffers.cpp[tag=bad_management,indent=0]
----
<1> Bug: the awaitable, rather than being ``co_await``ed, is returned to be used later.
    At that later time the array will no longer be alive. 


== Mutable versus Const Buffers

cpp:mutable_buffer[] represents the storage for bytes, intended to be written. The value
of the bytes is irrelevant, because they are overwritten. They may even have _indeterminate value_.

cpp:const_buffer[] represents bytes to be read. It is not only storage, it is also values.

[source,cpp]
----
include::example$snippets/5a_contiguous_buffers.cpp[tag=wrong_buffer,indent=0]
----
<1> Compiler error: passing cpp:const_buffer[] but the read operation needs to mutate its contents.


A cpp:mutable_buffer[] is convertible to cpp:const_buffer[]. Use this conversion with care.
It allows passing pure storage, possibly with indeterminate byte values,
to functions that read the byte values:

[source,cpp]
----
include::example$snippets/5a_contiguous_buffers.cpp[tag=buffer_conversion,indent=0]
----
<1> The storage starts with indeterminate byte values (intended to be overwritten).
<2> Bug: sends whatever the storage happens to contain.

== make_buffer

The convenience factory function cpp:make_buffer[] creates either
a cpp:const_buffer[] or cpp:mutable_buffer[] from your type. Your type must be
recognized as contiguous storage of trivially-copyable types.

cpp:make_buffer[] neither allocates nor copies. The result refers to the
storage of its argument, so that object must outlive every operation using
the buffer. A buffer made from a temporary, such as a `std::string`
returned from a function, dangles once the full-expression that created
the temporary ends.

== Representing Any Memory Region

Any memory region can be represented via cpp:const_buffer[]/cpp:mutable_buffer[], 
including a memory-mapped one:

[source,cpp]
----
include::example$snippets/5a_contiguous_buffers.cpp[tag=mmap_buffer,indent=0]
----
<1> A memory-mapped file
<2> A scope guard will unmap the memory at the end of the scope.
    cpp:write[] can throw, and the coroutine can be destroyed
    while suspended on `co_await`.
<3> Represent it as cpp:const_buffer[].
<4> Sends the mapped pages directly, with no intermediate read into user-provided storage.
