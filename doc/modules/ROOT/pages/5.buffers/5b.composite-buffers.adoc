= Composite Buffers
:page-mode: explanation

In real protocols, a message to be transmitted is often composed of a couple of chunks prepared separately
in separate contiguous regions of storage. For instance, you may separately get message headers, the payload, 
and the message checksum. Trying to get them into a single contiguous region would require the user to do
unnecessary copying.

To address this use case, all read and write operations in Capy allow you to provide ranges 
of contiguous buffers:

== Buffer Sequences

Capy introduces the concept of a _buffer sequence_.
It covers both a single contiguous buffer
and data produced in a number of contiguous buffers:

 * A contiguous buffer is a buffer sequence.
 * Any bidirectional range over contiguous buffers is a buffer sequence.

A range of buffers owns the buffers, not the bytes they refer to. Copying the
range copies the pointers and sizes, and each region of storage must still
outlive every operation using the sequence.

This generalizes the notion of a _handle_:

In the composite case, the range itself is the handle.
Its elements are cpp:const_buffer[] or cpp:mutable_buffer[], so copying the range copies the buffer descriptors, never the bytes.
Algorithms can copy the handle while the storage stays at its original location.

Treating a single contiguous buffer as a one-element sequence is intentional, to make the library API smaller. 
Internally, it is treated as a single-element range.

The structure looks two-dimensional, but the bytes across all contiguous buffers
are interpreted and transmitted as a single sequence. The bytes from the first
contiguous buffer come first, then the bytes from the second, and so on.

A sequence may hold any number of buffers, but a single operation does not always take all of them.
The type-erased streams, such as cpp:any_write_stream[], pass at most the first 16 non-empty buffers to each `write_some` or `read_some` call.
A longer sequence therefore takes extra calls, which cpp:write[] and cpp:read[] make for you.


=== The Concepts

Concept cpp:MutableBufferSequence[] tests if the type models a mutable buffer sequence,
suitable for read algorithms. It can be one of:

 * cpp:mutable_buffer[],
 * a bidirectional range of cpp:mutable_buffer[].

----

Concept cpp:ConstBufferSequence[] tests if the type models a const buffer sequence,
suitable for write algorithms. It can be one of:

 * cpp:const_buffer[],
 * cpp:mutable_buffer[] (with the caveat that its data has determinate values),
 * a bidirectional range of either cpp:const_buffer[] or cpp:mutable_buffer[].

These concepts are present in header `<boost/capy/buffers.hpp>`.

Every cpp:MutableBufferSequence[] is also a cpp:ConstBufferSequence[].

=== Your Own Buffer Types

A type of your own can act as a buffer when it converts to the buffer types.
To act as a const buffer, it satisfies cpp:ConstBuffer[] by converting to cpp:const_buffer[].
To act as a mutable buffer, it satisfies cpp:MutableBuffer[] by converting to cpp:mutable_buffer[] and to cpp:const_buffer[]:

[source,cpp]
----

----

A conversion to cpp:mutable_buffer[] alone is not enough.
Reaching cpp:const_buffer[] from it takes two user-defined conversions, and C++ allows one in an implicit conversion.
Algorithms read every mutable buffer sequence through cpp:const_buffer[], so the concepts reject such a type:

[source,cpp]
----
include::example$snippets/5b_composite_buffers.cpp[tag=mutable_only_type,indent=0]
----

Algorithms convert through a const reference, using both `const_buffer b = x;` and `const_buffer(x)`, and the concepts require both to compile.
Conversion operators that are `const` and return the buffer by value, as above, satisfy both.

A type that converts to cpp:const_buffer[] is treated as one buffer, even if it is also a range of buffers.
Its elements are ignored, and so are any conversions they provide.

Mark the conversions `noexcept`.
Algorithms call them inside `noexcept` functions, so a conversion that throws terminates the program.

=== Iterating Over Bytes

To treat a buffer sequence as one run of bytes, use cpp:buffers_begin[] and
cpp:buffers_end[]. They return a cpp:buffers_iterator[], an iterator that
crosses buffer boundaries and skips empty buffers. Standard algorithms can
then scan the data without copying it into contiguous storage:

[source,cpp]
----
include::example$snippets/5b_composite_buffers.cpp[tag=buffers_iterator_include]

include::example$snippets/5b_composite_buffers.cpp[tag=iterate_bytes,indent=0]
----

The iterator provides the random access operations, but they are not constant
time. Moving the iterator by `n` bytes walks the buffers it crosses, so jumps
are linear in the number of buffers. The sequence must outlive the iterators.
