* Error injection with cpp:test::fuse[fuse]

== Walkthrough

=== Mock Streams

[source,cpp]
----
include::example$snippets/8d_mock_stream_testing.cpp[tag=mock_streams,indent=0]
----

cpp:test::stream[test::stream] is a bidirectional mock that satisfies both cpp:ReadStream[] and cpp:WriteStream[]:

* Streams are obtained in connected pairs from `make_stream_pair(f)`; the shared `fuse` enables error injection
* `provide(data)`: Supplies data for the peer's reads
* `data()`: Returns data the peer wrote that this end has not yet read
* `set_max_read_size(n)`: Limits bytes returned per read, simulating chunked delivery

[source,cpp]

Use pointer construction (`&a`) so the cpp:any_stream[] wrapper references the stream end without taking ownership. This allows inspecting `b.data()` after operations.

=== Error Injection

[source,cpp]
----
include::example$snippets/8d_mock_stream_testing.cpp[tag=fuse_armed,indent=0]
----

`fuse::armed` runs the test function repeatedly.
Each run moves the injected failure to a later operation, until a run completes with no failure.
It does this in two phases: first the failures arrive as error codes, then as exceptions.

In this program, an error-code run returns `false` and increments `error`.
The clean run that ends each phase increments `success`, so `success` is 2.
An exception leaves the test body before either counter changes, so the exception runs do not appear in `Runs`.
