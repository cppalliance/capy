= Type-Erased Echo
:page-mode: how-to

Echo server demonstrating the compilation firewall pattern.

== What This Example Shows

* Using cpp:any_stream[] for transport-independent code
* Physical isolation through separate compilation
* Build time benefits of type erasure

== Source Code

=== echo.hpp

[source,cpp]
----
include::example$type-erased-echo/echo.hpp[tag=full]
----

=== echo.cpp

[source,cpp]
----
include::example$type-erased-echo/echo.cpp[tag=full]
----

=== main.cpp

[source,cpp]
----
include::example$type-erased-echo/main.cpp[tag=full]
----

== Build

[source,cmake,role=external]
----
add_library(echo_lib echo.cpp)
target_link_libraries(echo_lib PUBLIC Boost::capy)

add_executable(echo_demo main.cpp)
target_link_libraries(echo_demo PRIVATE echo_lib)
----

== Walkthrough

=== The Interface

[source,cpp]
----
include::example$type-erased-echo/echo.hpp[tag=session_decl]
----

Clients of this header:

* Can call `echo_session` with any stream
* Do not depend on implementation details
* Do not recompile when implementation changes

=== The Implementation

[source,cpp]
----
include::example$type-erased-echo/echo.cpp[tag=session_impl]
----

The implementation:

* Lives in a separate `.cpp` file
* Compiles once
* Can include any headers it needs internally

=== Build Isolation

When you change `echo.cpp`:

* Only `echo.cpp` recompiles
* `main.cpp` and other clients do not recompile
* Link step updates the binary
