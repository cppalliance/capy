= Async Mutex
:page-mode: how-to

Fair FIFO coroutine locking with cpp:async_mutex[].

== What This Example Shows

* Using cpp:async_mutex[] for mutual exclusion between coroutines
* RAII lock guards with `scoped_lock`
* FIFO fairness guarantees
* Comparing cpp:async_mutex[] to strand-based serialization

== Walkthrough

=== Creating the Mutex

[source,cpp]
----
include::example$async-mutex/async_mutex.cpp[tag=mutex,indent=0]
----

cpp:async_mutex[] is a coroutine-aware mutex. Unlike `std::mutex`, it suspends the calling coroutine instead of blocking the thread, allowing other coroutines to run while waiting for the lock.

=== Scoped Lock

[source,cpp]
----
include::example$async-mutex/async_mutex.cpp[tag=scoped_lock,indent=0]
----

`scoped_lock()` returns an cpp:io_result[] with an error code and an RAII guard. The guard automatically releases the lock when it goes out of scope. If the operation is canceled (e.g., via a stop token), `ec` is set.

=== FIFO Fairness

Unlike `std::mutex`, which has no fairness guarantees, cpp:async_mutex[] ensures FIFO ordering -- the first coroutine to call `scoped_lock()` is the first to acquire it.

=== Strand vs Async Mutex

The strand serialization example showed how a strand can protect shared state by running all coroutines sequentially. cpp:async_mutex[] provides finer-grained control: coroutines run concurrently and only serialize when entering the critical section.
