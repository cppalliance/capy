= Parallel Tasks
:page-mode: how-to

Distributing CPU-bound work across a thread pool and collecting results.

== What This Example Shows

* Running tasks in parallel on a cpp:thread_pool[]
* Collecting results with cpp:when_all[] xref:glossary.adoc#structured-bindings[structured bindings]
* Observing thread IDs to verify parallel execution

== Source Code

[source,cpp]
----
include::example$programs/8m_parallel_tasks_variadic.cpp[tag=full]
----

This page shows a variant that uses the variadic cpp:when_all[] overload, so each partial sum gets its own name.
The program in `example/parallel-tasks/` uses the range overload over a `std::vector` of tasks instead.
Both print the same output.

== Build

[source,cmake,role=external]
----
add_executable(capy_example_parallel_tasks parallel_tasks.cpp)
target_link_libraries(capy_example_parallel_tasks PRIVATE Boost::capy)
----

== Walkthrough

=== Partitioning Work

[source,cpp]
----
include::example$programs/8m_parallel_tasks_variadic.cpp[tag=partition,indent=0]
----

The range `[0, 10000)` is divided into 4 equal chunks, one per task. Each task computes a partial sum independently.

=== Parallel Execution with when_all

[source,cpp]
----
include::example$programs/8m_parallel_tasks_variadic.cpp[tag=when_all_variadic,indent=0]
----

cpp:when_all[] starts all four tasks concurrently on the thread pool. The result is cpp:results[results]`<long long, long long, long long, long long>`, a single `ec` plus the four partial sums in input order.

=== Observing Thread IDs

[source,cpp]
----
include::example$programs/8m_parallel_tasks_variadic.cpp[tag=thread_id,indent=0]
----

On a multi-core system you typically see different thread IDs, which shows the tasks running in parallel.
One worker can also take several tasks, so some IDs may repeat.
Building each line in an `ostringstream` and writing it with one `<<` reduces interleaving between threads.

=== Verifying Results

The sum of `[0, N)` is `N*(N-1)/2`. The example verifies that the sum of partial results matches this formula.
